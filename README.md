# PF Deal Portal

부동산 PF(프로젝트금융) 팀을 위한 **딜 관리 포탈**입니다. 외부에서 들어온 개발·PF 의뢰를 접수하고, 스크리닝과 수지 검토를 거쳐 투자자 모집 단계까지 진행 상황을 한 화면에서 관리합니다.

서버나 설치 없이 **`index.html` 파일 하나**로 동작합니다. 데이터는 사용자의 브라우저에만 저장됩니다.

> **바이브코딩 실습용 예제입니다.** 업무 프로세스를 그대로 화면으로 옮기는 과정을 보여 주기 위해 만들었습니다. 실제 딜 자료를 다루기 전에는 반드시 소속 기관의 정보보호 규정을 확인하세요.

---

## 업무 흐름

외부 의뢰 1건을 **딜 카드 1장**으로 관리하며, 7단계와 2개의 Go/Drop 게이트를 거칩니다.

```
① 접수 → ② 1차 스크리닝 → ◆ Gate 1 → ③ 개발 기획 → ④ 사업수지 검토 → ◆ Gate 2
      → ⑤ IM·수지표 작성 → ⑥ 투자자·대주 모집 → ⑦ 클로징
```

- **Gate 1**: 스크리닝 체크리스트에 '부적합' 항목이 하나라도 있으면 통과 불가 경고를 표시합니다.
- **Gate 2**: Downside 수지에서 선순위 상환 분양률과 LTV를 확인하고 결정합니다.
- Drop·보류 건은 사유코드와 함께 아카이브에 남고, 같은 소재지가 다시 접수되면 중복 경고를 띄웁니다.

## 주요 기능

| 메뉴 | 기능 |
|---|---|
| **대시보드** | 진행 중 딜, 이번 달 신규, 7일 내 기한, 보류 건수, 단계별 분포, 내 담당 딜, 최근 자료 |
| **딜 접수** | 필수 4개 항목(딜명·의뢰유형·자산유형·소재지)으로 등록, 딜코드 자동 부여(`2026-001`), 소재지 중복 검사 |
| **딜 파이프라인** | 7단계 칸반 보드, 드래그로 단계 이동, 자산유형·담당자·키워드 필터 |
| **딜 카드** | 개요 / 자료 / 검토·게이트 / 수지 요약 / 히스토리 탭, 핵심 지표 상단 고정 |
| **자료실** | 딜별 문서 등록, 문서유형별 버전 자동 증가, 표준 파일명 자동 생성 |
| **Drop 아카이브** | 사유코드별 집계, 재개 기능 |

### 1차 스크리닝 체크리스트 (7개 항목)

인허가 · 토지확보 · 분양·임대 · 시공사 · 공사비 · 금리·조달 · Exit

각 항목을 `적합 / 보완 / 부적합`으로 판단하고 근거 메모를 남깁니다.

### 수지 요약 산식

Base와 Downside를 나란히 입력하면 아래 지표가 자동 계산됩니다. 단위는 억원입니다.

$$
\text{사업이익률} = \frac{\text{총매출} - \text{총사업비}}{\text{총매출}}
$$

$$
\text{LTV(선순위)} = \frac{\text{선순위 PF}}{\text{담보가치}}
$$

$$
\text{선순위 상환 분양률} = \frac{\text{선순위 원리금} + \text{우선지급비용}}{\text{총매출}}
$$

PF 합계는 선순위·중순위·후순위의 합입니다. 상세 재무모델은 별도 수지표(엑셀)로 관리하고, 이 포탈에는 핵심 지표만 입력하도록 설계했습니다.

## 사용 방법

### 1. 내 PC에서 바로 열기

1. 이 저장소의 `index.html`을 내려받습니다.
2. 파일을 더블클릭해 Chrome 또는 Edge로 엽니다.
3. 처음 열 때 사용자 이름을 입력합니다. 비밀번호는 없습니다.

### 2. GitHub Pages로 공개하기

1. 저장소 **Settings → Pages**로 이동합니다.
2. **Source**를 `Deploy from a branch`로 선택합니다.
3. 브랜치는 `main`, 폴더는 `/ (root)`로 지정하고 **Save**를 누릅니다.
4. 몇 분 뒤 `https://<GitHub아이디>.github.io/<저장소이름>/`에서 접속할 수 있습니다.

> GitHub Pages로 공개하면 **코드는 누구나 볼 수 있습니다.** 딜 정보나 기관 내부 정보를 코드에 넣지 마세요.

## 데이터 저장 방식과 한계

| 항목 | 내용 |
|---|---|
| 딜·검토·수지 데이터 | 브라우저 `localStorage` |
| 업로드한 파일 | 브라우저 `IndexedDB` (1건 50MB 이하, 모든 형식) |
| 서버 전송 | **없음.** 입력한 데이터는 외부로 나가지 않습니다. |
| 팀원 간 공유 | **자동 공유되지 않습니다.** 사이드바의 `백업 내보내기` → 파일 전달 → `백업 불러오기`로 옮깁니다. |

**반드시 알아두세요.**

- 여러 명이 동시에 쓰는 용도가 아닙니다. `백업 불러오기`는 해당 PC의 데이터를 **통째로 교체**하므로, 각자 입력한 내용을 합치면 한쪽이 사라집니다.
- 브라우저 데이터를 삭제하면 포탈 데이터도 함께 지워집니다. 정기적으로 백업하세요.
- 브라우저는 파일 주소(경로)별로 저장 공간을 구분합니다. 파일을 다른 폴더로 옮기거나 다른 브라우저로 열면 기존 데이터가 보이지 않을 수 있습니다.
- 사용자 구분은 이름 입력 방식이라 **인증이나 접근 통제 기능이 없습니다.**

## 기술 구성

- 순수 HTML / CSS / JavaScript 단일 파일 (빌드 도구·프레임워크·외부 라이브러리 없음)
- 폰트: Google Fonts의 Noto Sans KR (오프라인이면 시스템 기본 폰트로 대체)
- 저장소 계층(`Local`, `Blobs`)이 화면 코드와 분리되어 있어, Supabase 같은 DB로 교체하기 쉬운 구조입니다.

## 로드맵
